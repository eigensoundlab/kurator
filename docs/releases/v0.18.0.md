# Kurator 0.18.0 – Copy, resample, rename, delete: file tools, quick destinations, delivery

## Highlights

Until now Kurator could move files but not copy, rename or delete them, so everyday file work still
needed Explorer or Finder. 0.18 brings it into Kurator, with a preview first and Ctrl+Z after:
copying (also for delivery to a client), resized copies, batch renaming, deleting to a trash,
cleaning up duplicates, and numbered destinations for sorting with one key.

### Copy to… (K)
The *Move* dialog, for copies; the originals stay where they are. Also in the status bar and in
**Files ▾**.
- **Any folder**, also outside the library: a delivery folder, a USB stick, a client's share. Year
  subfolders and the date in the file name work as for moves. Copying into the file's own folder
  makes `name (2).png`.
- **Dates kept and every copy verified** byte for byte; existing files are never overwritten.
- **Sidecars:** `.xmp` sidecars come along. Unity `.meta` and Godot `.import` / `.uid` files don't:
  they hold the asset's GUID, and a copy needs its own (the engine makes one).
- **Inside the library** the copies appear in the grid at once, with the original's tags, source,
  author and licence (an option), and its previews - same content, so nothing is indexed again.
  Copies into folders the scan skips (hidden ones, Unity's `Library/`…) stay out of the catalog.
- **Ctrl+Z** deletes the copies again, but only those still exactly as they were copied.

### Copies for delivery
*Copy to… → For delivery*, for sending work to a client, a shop or a print service.
- **Remove private details:**
  - the GPS location, camera and lens serial numbers, the camera owner, maker notes, user comments,
    the computer's name;
  - the **EXIF thumbnail**, which can show the uncropped original;
  - XMP and IPTC (editing history, document ids, sometimes a location) and JPEG comments;
  - PNG text chunks: **AI generation parameters** (A1111, Forge, Fooocus) and **ComfyUI
    workflows** are stored there.

  Kept: colour profile, orientation, resolution, dates, camera make and model, exposure.
- **Write the author and licence in**, from the side panel's *Source & licence*: XMP
  (`dc:creator`, `dc:rights`, `xmpRights:WebStatement` with the licence's link, `dc:source`), EXIF
  Artist / Copyright when cleaning, PNG `Author` / `Copyright`. Without cleaning, the author and
  licence are merged into the file's own XMP and its EXIF stays byte for byte.
- **As one zip archive** with a name you choose (pictures are stored, not compressed again). Names
  clash only inside the zip. Ctrl+Z deletes the zip.
- **No re-encoding:** for JPEG, PNG and WebP only the metadata blocks change; the picture data is
  copied byte for byte and decoded once afterwards to make sure it is intact. Other files are
  copied as they are; sidecars stay home.

### Resampled copies (I)
Smaller (or larger) versions of the selected pictures, as new files; the originals never change.
- **Size:** longest side, percent, width, height, fit inside a box, or an exact size (e.g. 512 × 512
  textures). Quick choices: 50 %, 25 %, 4096 … 512 px, *Pixel art ×2 / ×4*. Pictures already smaller
  are left out unless *Also enlarge* is on.
- **Filter:** Lanczos, bicubic, bilinear, area average (smooth reductions) or **nearest neighbour**
  for pixel art.
- **Format:** as the original (PNG, JPEG, WebP, TIFF, BMP, GIF, TGA), or PNG / JPEG / WebP with a
  quality (WebP 100 is lossless). Layered and other work files - PSD, Krita, SVG, HEIC, EXR… - are
  read through Kurator's own readers and saved as PNG. 16-bit greys (height maps) stay 16-bit in PNG
  and TIFF.
- **Where:** next to the originals, in a subfolder next to each (`resampled/`), or in one folder.
  The name ending is a pattern: `_{w}x{h}` (default: `hero_512x256.png`), `@{pct}`, or nothing.
- **Kept:** the colour profile, EXIF (with the original date; the pixel size in it is updated), dpi
  and the file time, so the copy sorts next to the original. Animated GIF / WebP / PNG keep every
  frame and its timing.
- In the library the copies appear with the original's tags, source, author and licence and are
  indexed in the background. It runs as a job with progress and *Stop*; Ctrl+Z deletes the copies.

### Rename (F2)
- **A name pattern** with parts: `{name}`, `{n}` (counter: start, step, digits, or `{n:3}`), `{date}`
  (`2024-05-31`, or `{date:%Y%m%d}`), `{year}` `{month}` `{day}` `{time}`, `{tag}` and `{tags}` (subject
  tags), `{project}`, `{folder}`, `{w}` `{h}`, `{author}`, `{ext}`. Ready-made patterns: *Date first*,
  *Folder + number*, *Tag + number*, *Project, tag, number*…
- **Find / replace** (also regular expressions) and **case** (lower, UPPER, Title).
- **Live preview.** The counter follows the order of the grid; files stay in their folders and keep
  their extension; clashes get ` (2)` and are highlighted.
- **Swaps and renumbering in place:** files are renamed in two steps (temporary names first), so
  `1, 2, 3` can become `2, 3, 4` or swap names. Case-only changes work on Windows too.
- Sidecars follow (XMP, Unity `.meta`, Godot `.import`), the catalog entry stays (tags, dates,
  stacks), and **Ctrl+Z** renames everything back.

### Delete (Del), to a trash you choose
- **Del** (or *Files ▾ → Delete…*) asks once, then deletes the selection with its sidecars, to:
  - **the system's Recycle Bin / Trash** (default, with [Send2Trash](https://github.com/arsenetar/send2trash)).
    Restore a file there and Kurator gives it its tags back, which are parked by content hash.
  - **or Kurator's trash folder** (⚙ Settings → Delete): Kurator's data folder when it is on the
    same disk, otherwise a hidden `.kurator-trash` folder at the top of that disk. Deleting is a
    rename (instant, everything kept). It is emptied after 30 days (or as you set; 0 = never) or with
    *Empty now*.
- **Ctrl+Z** brings files back from either, with their catalog entries, tags, source / author /
  licence and stacks - nothing is indexed again. From the system trash: the Windows Recycle Bin
  (read from its own index files), the desktop trash on Linux (freedesktop.org), the macOS Trash
  (found by name, size and time).
- **Safety:** on Windows, network shares and removable drives have no Recycle Bin, and a "recycled"
  file there would be gone for good. Their files go to Kurator's trash folder instead, and the
  message says so. Kurator never deletes anything for good except when you empty its trash folder.

### Clean up duplicates
**Clean up…** in the path bar of the *Duplicates* view (or *Files ▾*) keeps one copy of each file.
- **Which copy stays:** the one with the most tags, the oldest, the newest, the one with the shortest
  path, the one inside a folder you choose, or the one in the open project.
- Only files in the view (or the selection) are removed; the copy that stays may be elsewhere, and
  the preview says so.
- The copy that stays gets the tags of the removed ones (an option). The removed files go to the
  trash chosen in Settings; Ctrl+Z brings them back and takes the merged tags off again.

### Quick destinations (D, then 1–9)
Numbered folders that copy or move the selection at once, without a dialog - for sorting a pile of
new work with one hand.
- **D** opens *Send to…* with the numbered folders; press the number. **E** there (or *Files ▾ →
  Quick destinations…*) edits them: a folder, *Copy* or *Move*, and a name - e.g. *1 Delivery
  (copy)*, *2 Rejects (move)*, *3 References (copy)*.
- **Global, and per project:** a project's own destinations replace the global ones with the same
  number while it is open.
- Copies follow the rules of *Copy to…* (any folder, tags kept in the library), moves those of *Move
  to…* (inside the library). Ctrl+Z undoes them.

### Choosing folders
- **Browse…** next to every destination field - Move, Copy, Resample, Join / sheets, Export,
  Datasets, sound regions, quick destinations: click through drives and folders, make a **new
  folder**, or pick a **recent destination** or a pinned folder.
- **One list of recent destinations** for all of them, kept in the catalog (so it survives a browser
  change). ☆ pins a folder (also in the sidebar), × forgets it. Typed paths get the same suggestions.
- **Sidebar:** *Add* (library) and *Open* (Browse) use a typed or pasted path at once; with the
  field empty they read *Add…* / *Open…* and open the folder picker.

### Faster tagging
- **0 or Q repeats the last tag you used** (by hotkey, tag bar, T or dragging), so a tag without a
  hotkey is one key away. It is the first chip in the tag bar. In the viewer it is **Q** (0 fits the
  picture there).
- **Hotkeys per project** (*Edit…* on a project → *Hotkeys in this project*): a tag set for the
  project. While it is open, keys 1–9 apply its tags instead of the global ones - *1 Characters,
  2 Props, 3 Backgrounds* for a game, *1 Sketch, 2 Final* for a book. Keys left on *global* keep their
  tag; the tag bar and the sidebar show the keys that apply now.
- **Number keys without Shift** on keyboards that type letters on the number row (Czech, Slovak…):
  `ě š č ř ž ý á í é` count as 2…0.

### Per-project settings and the Files menu
- With a project open, Move / Copy, Resample, Join / sheet, Rename and Clean-up remember their
  settings and folders for that project - its delivery folder, its texture size - and fall back to
  the last ones used elsewhere.
- **Files ▾** in the status bar: Rename, Copy, Send to, Quick destinations, Resample, Delete, Clean
  up duplicates.

### Playhead 0.3.0
The vendored library is the unchanged Playhead 0.3.0 build (checksum in its README).
- New in the Look menu: *Tempogram* and *Repetition* for music, *Modulation spectrogram* and *Curve
  rhythms* for any sound, each drawn in place of the waveform at the viewer's zoom.
- The *Bar raster* folds time into a row per bar, which the viewer's cursor, selection, zoom and rows
  can't follow: it is offered for the grid thumbnails only.
- Sounds are analysed again with the new version when shown; stored analyses are kept per version.

### Fixes
- **Old scripts after an update:** the UI's own files had no caching instruction, so browsers kept
  them for a time they guessed from the file's age (days for files unchanged since the download), and
  a normal reload could go on running old code. They are now sent with `Cache-Control: no-cache`:
  the browser asks every time and gets a quick 304 while a file is unchanged.
- Escape in a dialog opened from another one (the folder picker) closes only that one.
- Tests: the KTX2 zstd test runs on Python 3.14 (built-in `compression.zstd`), and the CMYK profile
  test no longer expects the test profile first (macOS lists its *Generic CMYK Profile*).

## Upgrading
- Run **update.bat** / **update.sh** (or install.bat / install.sh): it installs the new dependency,
  **Send2Trash** (BSD-3, pure Python).
- The catalog is migrated to schema 12 on the first start (one new table); nothing is indexed again.
- Coming from 0.17, press **Ctrl+F5** once in the Kurator tab, so the browser drops the scripts it
  kept from before. From 0.18 on a normal reload is enough.

## API
- `POST /api/copy/plan`, `POST /api/copy` `{ids, dest, by_year, date_prefix, keep_tags, clean, credit, zip}`
  – any folder; the answer has `copied`, `indexed`, `new_ids`, `cleaned`, or `zip`.
- `GET /api/resample/options`, `POST /api/resample/plan`, `POST /api/resample/run`
  `{ids, mode, value, value2, enlarge, filter, format, quality, where, folder, suffix, keep_date, keep_tags}`,
  `GET /api/resample/job`, `POST /api/resample/cancel`.
- `POST /api/rename/plan`, `POST /api/rename` `{ids, template, start, step, pad, find, replace, regex, case}`.
- `POST /api/delete` `{ids, mode?}`; `GET /api/trash`; `POST /api/trash/empty`. Settings:
  `delete_mode` (`system` | `kurator`), `trash_days`; `GET /api/settings` also has `system_trash`.
- `POST /api/duplicates/plan`, `POST /api/duplicates/clean` `{ids, keep, folder, project, merge_tags}`.
- `GET /api/folders/recent`, `POST /api/folders/recent/forget`, `POST /api/fs/mkdir` `{parent, name}`.
- `GET /api/send-slots`, `PUT /api/send-slots` `{scope: "global" | project id, slots}`.
- `PUT /api/projects/{id}/hotkeys` `{hotkeys: {"1": tag id, …}}`; `GET /api/projects` has `hotkeys`.
- `POST /api/operations/{id}/undo` also undoes copies, resamples, renames and deletes.
- Catalog schema 12: `project_hotkeys`. Moves, copies, sheets, exports, datasets and resamples into a
  folder record it as a recent destination.
