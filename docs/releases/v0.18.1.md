# Kurator 0.18.1 – Drop files onto Kurator; fixes

## Highlights

### Drop files onto Kurator
Drag files from Explorer, Finder or a web page onto Kurator to tag them or bring them into the
library.
- **Where you drop decides the tags:**
  - onto a tag or project (sidebar, tag bar, the project chip in the path bar): the files get it;
  - onto the grid: they get the open project and the tags the view is filtered by.

  While you drag, a banner says what the drop will add.
- **Files already in the library** are recognised by name, size and modified time and tagged where
  they are. A web page never sees where a dropped file is - only its name, size, time and bytes - and
  those three together find it in the catalog (with 2 seconds of leeway for FAT drives).
- **New files** - a download, an image from a website or a chat - are **copied into a folder you
  choose** (remembered per project). They keep their modified time, are indexed when the folder is in
  the library, then tagged. Names never overwrite; kinds of files Kurator doesn't show are left out,
  and so are folders (add those with *Add…* in the sidebar).
- **One confirmation** lists both groups, with **Don't ask again**; ⚙ Settings → *Dropping files*
  turns the question back on.
- **Ctrl+Z** takes the tags off again (and puts back a status or source the drop replaced) and
  deletes the copied files.

### Fixes
- **Case-only renames on macOS:** renaming `shot1.png` to `SHOT1.png` planned `SHOT1 (2).png`,
  because macOS disks ignore case and the new name seemed taken. The planner now asks the file
  system which file a name points to. Windows and Linux were not affected.
- **Tests on Windows and macOS:** the test for that fix imitated a case-insensitive disk in a way
  that only works on Linux; it now works on every system.

### CI: failures on one page
When tests fail, the run's **Summary** page lists, for every failing job, the OS and Python version,
the counts, and per failed test its name, message and the end of its traceback - ready to copy
(`tools/ci_failures.py`). If the tests never ran, it says so.

## Upgrading
- Nothing to install; restart Kurator after updating.

## API
- `POST /api/drop/match` `{files: [{name, size, mtime}]}` – the catalog ids of dropped files.
- `POST /api/drop/file?batch=&dest=&name=&mtime=` with the file's bytes as the body; `POST /api/drop/done`
  `{batch}` – one operation for the received files (Ctrl+Z deletes them).

## Tests
- `tests/test_v18_files.py`: dropped files matched (case, size, FAT time), received (own name,
  modified time, catalog row, outside the library, kinds refused), undone; the case-insensitive
  rename plan on every system.
- `tools/ui_check_v18_files.py`: drops a known and a new file onto a sidebar tag, undoes it, drops
  again without asking.
- pytest: 185 passed on Python 3.13 and 3.14.
