# Kurator 0.15.0 – Basis Universal textures, HDR pictures, PDF pages, datasets, licences

## Highlights

### Basis Universal textures (KTX2)
- **ETC1S and UASTC** textures (`.ktx2` with BasisLZ or UASTC, also Zstd-compressed) now get real
  thumbnails and open in the viewer. This covers what game engines, glTF tools (gltfpack,
  KTX-Software's `toktx`, Blender exporters) and the Basis encoder write.
- Kurator decodes them itself: `kurator/basisu.py` is a Python and numpy port of the decoding parts
  of the official transcoder (Binomial, Apache 2.0). No new package or download is needed, on any
  system.
- It was checked **pixel for pixel** against the official tool on photos, alpha, grey + alpha,
  every quality level, all 19 UASTC block modes and mip levels. The tests compare with pictures the
  official tool unpacked (`tests/data/basis`).
- Thumbnails decode the **smallest mip level** that is still big enough, so big textures are quick.
  This now also applies to the other KTX2 formats (BC, ETC2, ASTC...).
- **glTF with `KHR_texture_basisu`**: the KTX2 maps show in textured thumbnails and in the 3D viewer.
- Two-channel textures (normal maps stored as R + G) show as red/green.
- The newest Basis formats (UASTC HDR 4x4, ASTC/UASTC HDR 6x6, XUASTC LDR, XUBC7) and HDR ASTC
  textures go through the **official `basisu` tool** if it is installed: on the PATH, or set
  `KURATOR_BASISU=C:\path\to\basisu.exe`. Without it they show a card that says so.

#### About the decoders you suggested
- **tex2img** has wheels only for Python 3.6–3.8 (the last release is from years ago), so it
  can't be installed on Python 3.11+.
- **alktx2** has wheels for Windows and Linux only (no macOS) and declares no licence. It also
  bundles its own copies of libtiff and libwebp.
- **SimVX-Textures-Basis** exists only as development pre-releases. It needs Python 3.14 or newer
  and is licensed AGPL-3.0, which doesn't fit an Apache-2.0 app.
- The official **`basisu` tool** is used as the fallback, as you suggested, for the formats above.

### HDR pictures: OpenEXR and Radiance
- `.exr` and `.hdr` files are indexed and shown **tone-mapped**.
- **OpenEXR:**
  - scanline and tiled (also mip-mapped);
  - uncompressed, RLE, ZIPS and ZIP compression (the defaults of Blender, Nuke, Houdini and most
    renderers);
  - half, float and uint channels;
  - colour from the main layer or a layer such as `beauty.R`;
  - a single channel such as depth (Z) is shown from its lowest to its highest value.
  - PIZ/PXR24/B44/DWA files get a card for now.
- **Radiance RGBE** (`.hdr`): flat or run-length encoded.
- Big HDRIs are read with a stride for thumbnails.
- The side panel shows the channels, compression and the brightest value.

### PDF pages in the viewer
- Multi-page PDFs (and PDF-based Illustrator files) show a page bar: **‹ Page 3 / 12 ›**.
  - `[` `]` or Page Up / Page Down turn pages; you can also type a page number.
  - Pages of different sizes keep their own size.
  - The trim/bleed boxes follow each page.
- **Zooming in renders the page again at the size you need**, so text and vectors stay sharp, up to
  8000 px.

### Vision models through OpenAI-compatible servers
- Tag pools that use a vision-language model, and captions, can now use **any OpenAI-compatible
  server**, besides Ollama:
  - llama.cpp's `llama-server` with a vision model (`--mmproj`);
  - LM Studio's local server;
  - vLLM, LocalAI, Jan.
- *AI → Vision model server*: choose the server, its address and an optional API key. *Check*
  lists its models.
- Kurator asks for JSON with a fixed list of allowed tags (`json_schema`), so the model cannot
  invent tags. Older servers that don't support that get the plain JSON request.
- The API key stays in your settings and is never sent back to the browser.
- These servers usually run on your own computer. An internet address sends the pictures to that
  service.

### Training datasets
- *AI → Training dataset → Export…* (also without the AI add-on) writes the selection or the
  current view as a **dataset**:
  - each picture with its caption in a `.txt` next to it;
  - a `metadata.jsonl` (`file_name`, `text`);
  - this is what kohya-ss sd-scripts, OneTrainer, ai-toolkit, SimpleTuner and diffusers read.
- **Captions** come from the AI captions (vision models), from tags (choose the tag groups), or
  both, with an optional **trigger word** first.
- **Identical files once**, and **near-duplicates once** (the same picture resized or re-saved).
  The biggest copy is kept, with the best caption and all the tags of its copies.
- **Size and format:**
  - optional downscaling (longest side 512–2048);
  - keep PNG/JPEG/WebP, or convert all;
  - PSD, Krita, SVG, HEIC and other formats are converted through Kurator's previews;
  - transparency kept or flattened onto white.
- **Train/validation split** with a seed: the same settings give the same split.
- `kurator_dataset.json` lists every file's original path, caption, source, author and licence.

### Source, author and licence
- The side panel has **Source & licence**: where a file came from (URL, shop, book…), who made it,
  and its licence.
  - Common licences are suggested (CC0, CC BY, CC BY-SA, CC BY-NC…, Own work, All rights
    reserved…), with a link to the licence text.
  - With several files selected, *Copy to the N selected* gives them all the same values.
- **Search:** `source:artstation`, `author:jane`, `licence:cc-by`, and `licence:none` for files
  without a licence. Plain words in the search box also look in these fields.
- Written into **XMP sidecars** (`dc:source`, `dc:creator`, `dc:rights`, and
  `xmpRights:WebStatement` for known licences).
- Listed in project exports and dataset manifests.
- Like tags, they follow a file that is moved or renamed outside Kurator.

### XMP sidecars of other programs
- New option in ⚙ Settings: **Also update sidecars of other programs** (Lightroom, darktable,
  digiKam, Bridge).
  - Kurator adds its keywords to the keyword lists already there. Their keywords and everything
    else (develop settings, ratings, history) stay exactly as they were.
  - Source, author and licence are added only where the sidecar has none.
  - Before its first change to such a file, Kurator keeps a copy in its data folder
    (`xmp-backup`).
  - A sidecar whose namespaces Kurator can't trust is left alone and reported.

### Backup schedule
- A backup set can **remind you every N days** (day, week, month…). A *Backup due* button shows in
  the status bar.
- Or it can **back up by itself** while Kurator is open, when the target disk is connected.
  Otherwise you get the reminder.
- Each run copies only what changed.

## Other changes
- The side panel shows texture facts for KTX2 files: format, mip levels, sRGB, alpha, two-channel.
- KTX2 supercompression errors in damaged files are reported, not raised. A fuzz test covers the
  Basis decoder.
- `tools/make_basis_fixtures.py` re-creates the Basis test textures with the official encoder.
